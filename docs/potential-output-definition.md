# “潜在产出”的原版定义核对

2026-11-19，核对本机 CK3 Florin 1.21.0 原版文件。按用户要求先暂停实现，澄清展示对象。本记录是数据与界面定义核对，不代表新子 mod 已实机通过。

## 结论

“潜在产出”表示**这个伯爵领具有生产哪些资源商品的潜力**，决定县首府的资源地产可以生产哪些原材料。它是商品种类的集合，不是当前已生产的商品清单，也不是预计月产量、市场存货、进口商品或最高产出的商品。

原版简中概念 `game_concept_potential_production_desc` 明确写道：

> 每个伯爵领的潜在产出决定了伯爵领首府的资源地产能生产什么原材料贸易商品。

同文件的 `game_concept_production_desc` 则将“生产量”定义为地产和建筑每月生产的贸易商品数量。两者是不同数据。

## 原版证据链

以下路径均相对于配置提供的游戏 `game/`，没有将原版文件复制进产品。

| 文件 | 核对内容 |

| `gui/window_county_view.gui:5691` | 伯爵领界面的 `potential_trade_goods` 区域 |

| `common/districts/resource_districts.txt:39` | 林业地产通过 `has_potential_for_trade_good = trade_good_type:trade_good_wood` 判断县的木料潜力 |

潜力表是一套独立的县级配置，不能根据当前建筑、当前出产商品或地形名称反推。尚未建造对应资源地产、当前产量为零，也不应因此排除该县的潜力商品。具有潜力也不等于立刻满足建筑的一切其他条件。

## 对子 mod 需求的具体约束

1. 每个伯爵领显示其原版“潜在产出”集合，读取与原版伯爵领面板相同的数据。
2. 筛选后的显示集合 = 该县潜在产出 ∩ 面板勾选商品。勾选“铁”，应显示具有铁潜力的县，即使那里尚无铁产量；勾选“铁、盐”，应同时显示这两种潜力。
3. 本版本贸易商品共 44 种，但县级潜力配置只有 **35 种**。另外 9 种没有县级潜力配置：腌肉、奶酪、啤酒、纺织品、皮革、玻璃、珠宝、漆器、书籍与纸张。原版 `resource_districts.txt:1` 也将这些商品列为没有主资源／潜力建筑的商品。不能把加工生产的可能性混入这个“潜在产出”集合。
4. 先前候选面板把 44 种全商品都列为可选项，范围过宽，需要按本定义纠正；已有地图数据绑定确实指向潜力列表，但地图绘制仍未通过实机验收。

## 可用的地图深浅指标

已查的原版县级潜力表只保存“商品 → 具有该潜力的县”关系，没有储量、潜在月产量或最大产能字段。原版县面板也绑定商品列表。资源建筑中的 `province_potential_trade_good_modifier` 是按潜力条件施加的建筑生产修正，不能直接当作县的潜力数量。

可以从集合导出**符合当前筛选的潜力商品种类数**：

`数量 = |该县潜在产出集合 ∩ 勾选商品集合|`

- 勾选全部：用该县潜力商品种类总数表示深浅。
- 只勾选铁：只能得到无铁潜力／有铁潜力两档；原版数据不能据此区分两个有铁潜力的县哪个铁矿更多。
- 勾选铁和盐：零种用灰色，具备其中一种用浅色，两种都有用深色。
- 全部取消：所有县为零，不再显示潜力商品图标。

本机原版表涉及 3,549 个不同伯爵领，去重后各县潜力种类数分布如下。只统计表内配置，不声称覆盖所有可点击地块，也不把这些静态统计称作实机渲染通过。

| 潜力种类数 | 伯爵领数 |
| --- | --- |
| 2 | 189 |
| 3 | 743 |
| 4 | 1,621 |
| 5 | 993 |
| 6 | 3 |

因此 0–6 档的图例具有明确数据意义。颜色代表潜力种类丰富度，不代表生产效率、单商品储量或经济收益；后几项需要额外定义指标，不能冒充原版潜力数值。该着色指标是需求设计建议，具体引擎绘制路径尚未实现或验收。

统计与源文件摘要见 [精简证据](evidence/potential-output-definition.json)。归属决定：本记录的概念核对、版本统计、县级例子和需求约束服务本产品，留在本项目。通用 GUI 地图图层与接口发现只有在验证后才考虑富化框架，不把当前失败候选变成通用通过结论。
