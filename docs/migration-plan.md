# More Tenets Slots(XA) 新版 CK3 迁移计划

日期：2026-10-02。起点：`a7eacf9`，产品目录 `more_tenets_slots_xa_dev/`，旧声明 `1.19.0`，产品版本 `9`。当前目标为 CK3 `1.20.0.3 (Crozier)`；最终绑定本机实际 launcher/build/EXE SHA 和原版文件 SHA。官方更新入口：[CK3 官方公告](https://store.steampowered.com/news/app/1158310)。框架当前安装识别目标也是 `1.20.0.3`，历史报告不能代替本机输入。

## 工作包及次序

1. **规则与计划先行**：提交本计划、测试验收计划及根 `AGENTS.md`；登记框架任务总线，检查两个仓库状态和已有工具。每个包必要验证后立即主线提交推送。
2. **冻结输入与兼容分析**：识别实际游戏安装和精确版本，冻结文件清单/哈希；对照信仰查看/创建 GUI、教义组、全部真实核心教义、空槽、信仰创建 on_action、清理事件、文化 tradition define、本地化与 descriptor。检查同名顶层覆盖，不以路径不同判断无覆盖。发现不兼容时先落盘证据。
3. **最小迁移**：以新版原版正文更新 GUI 和教义定义，保留 100 槽、空槽清理和 10000 tradition cap 的既有意图；复用新版原生过滤、费用、选取限制及其他新增行为。避免用老版完整复制覆盖新版原生机制。必要时采用可逆、可校验的生成投影，并将通用投影能力富化到框架。版本声明只在实际源码适配后更新。
4. **静态与构建验收**：按测试计划运行确定性预验、脚本/BOM/引用/覆盖审查及可重复构建。产品配置与报告留在本仓库；通用检查、解析、投影、日志和构建能力优先提交框架。
5. **隔离实机验收**：使用框架受管能力、新 userdir 和外置测试夹具；检查新版日志、信仰面板、创建/改革、空槽清理、费用与存读档，再检查文化传统界面。Steam 保持离线，本机进程/owner/排他槽必须符合框架合同。旧版证据不计新版通过。
6. **交付**：提交迁移报告、明确实际通过项与剩余项、运行命令、精确版本和证据索引；普通推送 `master`。本任务为兼容迁移，不包含 Steam Workshop 发布。POD 两产品留待独立范围。

## 关键风险与完成标准

- 信仰 GUI 和完整真实 tenet 覆盖会丢失 1.20 宗教重构；须逐项保留新版行为，而非只改 supported_version。
- 100 槽的 UI、重复选择和费用必须验证实际原生效果；10000 tradition cap 是上限扩展，不能声称已验证 10000 个实际传统。
- 信仰创建的原生钩子必须保留；同名 on_action 覆盖与作用域变化均须核对。
- 现有内层 descriptor 含 Workshop ID，按框架规范将其移出正式内层树；已有 Workshop 身份记入产品文档，外层注册由隔离验收配置提供。
- 完成适配须静态及新版实机关键路径均有证据。缺游戏源文件、进程占用或验收能力时明确记录环境缺口，继续所有可独立完成的工作，不伪报完整兼容。
