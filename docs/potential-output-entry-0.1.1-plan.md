# 潜在产出 0.1.1：入口改造与自测计划

2026-11-20，用户已授权施工、自测，随后要求优先研究「＋」展开后的末尾独立分组及兼容性。悬停标题确定为「潜在产出（XA MOD）」。

## 范围与选择

放入展开菜单本身不能消除冲突：原版没有末尾自动追加列表接口，`mapmodes_insert_before` 仅为前插 block。可尝试以产品独立 GUI 文件重定义**仅** `flowcontainer_additional_mapmodes`，保留原版 `map_modes`、`hud.gui`、`shared/buttons.gui` 和 `shared/mapmodes.gui` 文件。相较覆盖常驻视角栏，这能缩小影响范围；但与重定义同一个展开菜单类型的 Mod 仍可能冲突，不能称完全兼容。类型加载顺序、目标实例采用和真实可见性必须实机验证。

最终位置等待用户对上述兼容边界的文字澄清；这不是再次申请施工许可。期间继续与位置无关的版本来源核对、入口样式、筛选面板收起和状态流改造。若选择展开菜单，放在全部原版地图视角之后、「其他地图设置」之前，以分隔线、`XA MOD` 标题和独立一行展示；若选择常驻栏，按既有研究的末尾位置施工。

候选施工决定：向用户说明无法消除同类型冲突，并提供文字选项后，按其最新表达偏好的「＋」末尾独立分组制作候选。候选只定义 `flowcontainer_additional_mapmodes`，不覆盖原版 mapmodes/hud/buttons 文件，具体兼容资格仍待实测；若用户改选常驻位置，沿用同一入口控件调整挂载点。

用户后续明确选择常驻末尾，并进一步要求不改变原生视角栏、只制作外观类似的独立圆形按钮。此最新要求覆盖前述候选：最终通过 scripted_widgets 独立注册按钮，优先相对原版宗族按钮锚定，原生「＋」仍占据其原位置；根据实机边界留出空白，按钮不得遮挡原版或越出屏幕。不新增任何同名原版视角类型，也不覆盖 mapmodes/hud/buttons。旧的弹出类型候选只留本机研究材料，不进入运行包。兼容边界限于“入口不新增视角栏覆盖”，原有三份地图/活动 GUI 覆盖仍须分别考虑。

## 施工

1. 冻结 1.21.0.3／26785313 当前 EXE 与原版依赖。逐个核对原有七份输入 hash，新增 GUI 类型来源也单独绑定。旧版实机与发布证据保持原版本范围。
2. 将候选版本设为 0.1.1；复用原版圆形框和资源图标，加 `MOD` 标记及九语言同键本地化。入口使用独立回调，避免通用地图按钮默认 SetMapMode 抢先覆盖原视角。
3. 点击入口后由真实活动说明窗口上下文完成初始化及自动进入。原显示地图按钮保留为初始化失败时的可见后备；单击直达须实测。
4. 将面板收起为原位置的窄标题条，提供展开和退出；不再依赖旧底部矩形按钮找回筛选。保留延迟重选选项与评分刷新控制器。
5. 更改退出/重新打开后继续恢复原视角、重置或保留筛选的既有约定；普通活动规划不解锁、不启动展示活动。

## 验证

- 静态：生成 allowlist、原文 hash、原版恢复/类型抽取回查、九语言 BOM/格式/键集、实际筛选表达式回归、双构建一致及独立 Workshop 身份。
- 类型兼容范围：确认运行包不覆盖原版 mapmodes/hud/buttons 路径；明确仅新增一个同名弹出类型。若需进一步验证主栏类型独立，可用隔离外置夹具标记主栏，不能冒称覆盖全部第三方 Mod。
- 简中实机：原版「＋」展开及原按钮保留、末尾分组、悬停全文、单击进入、单选/多选/清空更新、收起标题条与恢复筛选、退出原视角、再次进入默认全选、普通活动规划回归、旧存档加载及正常退出。
- 使用共同 GUI-only 生命周期，MCP-first 缺口留证，Steam 离线、CK3 排他、冻结源码、原 Popen、keeper 和 CAS 正常闭合。失败修正后分配新场，不热改冻结输入冒充正式通过。
- 本包目标是施工与自测。正式发布、更新工坊描述和新版截图分别记录，不能把静态通过称实机通过，也不把 0.1.0 工坊版追认为候选代码。

归属：产品源码、布局和具体证据留本仓库；安装识别、结构解析、可逆投影、日志、构建及受管生命周期复用框架。若形成新的可复用 GUI 类型加载/兼容经验，在实际验证后考虑富化框架，不搬入产品源码或原版大段素材。
