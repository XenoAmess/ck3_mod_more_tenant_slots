# 潜在产出：接入原版地图视角栏的研究

2026-11-20。用户要求研究将目前生硬的独立按钮放到右下角视角组末尾，并明确体现 Mod 身份。本包只做本地源码研究、插入点结构验证与设计建议，未修改运行文件、启动游戏或更新工坊。

## 建议

**接入右下角常驻视角组，在「＋」右侧追加一个专用圆形按钮。** 采用原版圆框与悬停反馈，资源图案用青绿色，铜金色外环，右上角加深底浅字的 `MOD` 小角标。建议按钮约 40×40 GUI 单位，稍大于该排原版的 32×32；与「＋」之间留约 6–8 单位间距。尺寸、角标字号和行宽在实际 UI 缩放下调校，不将这些建议数值当成已验收布局。

```text
原版常驻下排：  [宗教] [文化] [宗族] [＋]
建议下排：      [宗教] [文化] [宗族] [＋]  [资源图案·MOD]
```

悬停标题为「潜在产出（XA MOD）」，正文说明「查看各伯爵领可以生产的商品，包含尚未开发的资源」。`MOD` 直接说明来源，图案表达用途；启用后保持选中外环。依靠轮廓、图案和文字共同区分，不依靠闪烁或单一颜色。

| 位置 | 研究结论 |
| --- | --- |
| 常驻视角组末尾 | 推荐。直接可见，符合在地图视角区域查找功能的习惯，代价是扩大这一组的布局空间。 |
| 「＋」展开的更多视角列表末尾 | 源码可插入，但需要展开才能发现。原版该列表末尾附近已有生产与市场视角，语义相近，可作备选。 |
| 现有独立文字按钮 | 当前实现为固定屏幕偏移的 140×36 矩形，与原版视角组没有布局关系，是本次替换目标。 |

推荐的交互目标：未启用时点击进入潜在产出并显示筛选；启用时点击恢复/展开筛选，保留当前选择。减号只收起面板，叉号退出并恢复此前视角。单击直达、无需现有「显示地图」第二步是更顺畅的目标，但原生规划器有先打开说明窗口、再 Confirm 的初始化流程，须在其真实上下文就绪后衔接并实测，不能简单串接一次 onclick 就宣称成功。

## 原版源码依据

本机当前 EXE 与上次发布后的 1.21.0.3／build26785313 身份相同。此次读取的是当前磁盘原版文件，文件摘要和行号见[研究证据](evidence/potential-output-mapmode-entry-research.json)。

- `gui/shared/mapmodes.gui:97` 定义 `map_modes`，基础区域固定为 170×95，包含背景、左侧领地按钮和右侧两排按钮。
- 同文件 `271–410` 是右侧布局；`335–409` 的下排依次为宗教、文化、宗族，以及切换 `mapmodes_expand` 的「＋」。该「＋」是匿名 widget，不能凭空引用不存在的稳定 widgetid；真实追加位置是它后面的同级布局子项。
- `gui/hud.gui:2644` 实例化 `map_modes`，位于原版底部 HUD 的布局容器中。应让新增按钮参加这个布局，并配套调整宽度与背景，避免继续靠独立窗口的屏幕坐标模拟位置。
- `gui/shared/mapmodes.gui:472` 是另外一套「更多视角」弹出容器。它由 `mapmodes_expand` 控制；`mapmodes_insert_before` 是现有的前插 block，此文件没有对应的 `mapmodes_insert_after`。不能把前插点说成常驻栏末尾的现成扩展点。
- `gui/shared/buttons.gui:1127–1177` 的 `icon_button_mapmode` 依赖 `MapMode` 上下文：默认点击执行 `SetMapMode(MapMode.GetKey)`，按 `IsMapMode` 决定选中状态。其 `mm_button` 空 block 位于默认 onclick 后面；仅在该 block 中追加回调，不能假定已替换默认切图动作。

因此，可沿用 `button_round` 的外观，为本产品单独定义点击和选中状态，避免默认切到 realms 后才保存「原视角」。潜在产出仍以专用规划器是否打开来判断激活，不把原版 realms 的选中状态当成本 Mod 的选中状态。

## 实现时需要处理的边界

1. **激活后的入口不能消失。** 原版常驻布局多层使用 `CanChangeMapMode` 控制可见性。当前潜在产出占用活动规划器，必须实测这时的原生锁；若被锁，须只为本产品激活状态保留入口和选中显示，不整体解除普通活动规划的地图限制。原版其他视角的点击切换若要直接退出本模式，也要先关闭专用规划器，再执行目标切图，不能留下仍在工作的评分层。
2. **布局空间与原版状态必须一起核对。** 地图按钮组有固定宽度，不能只追加后默认不会重叠。要检查右侧边界、背景、领地大按钮、时间条、更多列表，以及商人政府切换后的上排。该 `map_modes` 类型也被多人大厅使用；新增入口须只在实际战役 HUD 可用，不能把活动规划入口暴露给大厅。
3. **保留过滤刷新控制器。** `dev_tools/potential_output.py:393–435` 的 `xapo_view_controls` 同时含旧矩形按钮和延迟刷新用的隐藏动画子控件。替换旧按钮时不能删除整个类型，否则会连带删掉选项重选与评分刷新。应迁移/保留非显示控制部分，只移除被替代的矩形入口。
4. **新增覆盖的兼容范围。** 目前产品覆盖三份原版 GUI。首选做法是再对 `gui/shared/mapmodes.gui` 做 hash 固定的最小可逆投影，新增类型放产品自身 GUI；不为此复制整份 `hud.gui` 或修改全局 `buttons.gui`。这会新增与其他改写地图视角栏 Mod 的同路径冲突，须在说明中增加该文件。这里是实现方案，尚未加入运行包。

## 后续施工与验收计划

先在生成器中加入专用圆按钮、资源图案、角标和提示本地化，将原版常驻下排的唯一末尾锚点纳入原文 hash 合同。移除独立文字入口，保留评分刷新控制器；完善入口、说明初始化、激活、收起、重开和退出的状态流，再生成候选版本。

静态检查包括原版投影逆恢复、允许修改清单、本地化九语言结构、默认 SetMapMode 回调不误触发、普通规划器限制不被放开。已有构建工具仍固定 1.21.0；本机是 1.21.0.3，实际施工须先核实并更新精确版本来源合同，不能为了构建只改版本号或绕过该拒绝。

实机只用简体中文：核对默认/放大 UI 的末尾位置与 `MOD` 角标可读性；检查商人/非商人布局、更多菜单及右侧边界；从政治、文化等视角进入并退出后恢复；激活期间入口可见、选中正确；单选/多选/清空仍刷新；收起再展开保留筛选；原版活动规划正常；大厅不出现错误入口；正常退出并收集日志。只有这些通过后再更新工坊与对应实际截图。本研究未授予上述实机通过。

本包仅对候选插入做结构扫描及正反投影检查，未验证引擎语法、点击、图标渲染、可见性或最终布局。

归属决定：本产品入口布局、行为建议及 exact-build 证据归本仓库；结构扫描和可逆投影复用框架已有合同。本次没有新增通用能力，无需修改框架；模板默认回调和可见性是本次原版来源的具体事实，不外推为所有游戏版本或所有 GUI 的合同。
