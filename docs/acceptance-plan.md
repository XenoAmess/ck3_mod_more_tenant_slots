# More Tenets Slots(XA) 测试验收计划

日期：2026-10-02。目标 CK3 `1.20.0.3`，只覆盖 `more_tenets_slots_xa_dev/`。本计划须在迁移实现前提交。

## 静态与离线预验

| ID | 检查 | 验收条件 |
| --- | --- | --- |
| L0-01 | 输入身份 | 当前 launcher version、Steam build（可取得时）、EXE 与所有依赖原版文件 SHA 入报告；不引用他机绝对路径作为本机证明 |
| L0-02 | 原版变更 | 两处 GUI 与全部同名顶层教义/组/钩子对照；原版新增行为保留，产品差异可解释 |
| L0-03 | 确定性解析 | 优先判断 `open_kaishek` 可覆盖子集并执行；不支持项/环境缺席单列，再使用框架已有解析能力。不能以离线结果代替 CK3 |
| L0-04 | 产品合同 | 100 核心槽、空槽 ID 完整且唯一、清理覆盖所有空槽、费用与限制保留；tradition define 为 10000；中英文必要 key 存在，脚本及 yml BOM 正确 |
| L0-05 | 投影与发布树 | 从新版源生成的差异仅含授权产品变更；重复生成相同；正式包不含夹具、报告、作者许可截图或内层 remote_file_id |
| L0-06 | 构建 | 两次构建 manifest/ZIP 相同，文件 allowlist 明确；语法/引用 RED 均已闭环 |

## 新版实机关键路径

| ID | 场景 | 验收条件 |
| --- | --- | --- |
| L1-01 | 启动与加载 | 本机唯一受管 CK3，隔离 userdir，证明加载本次精确产品树；新增产品解析错误为零，原版 baseline 错误单列 |
| L1-02 | 查看信仰 | 普通信仰、代表性新版信仰与已扩槽信仰窗口正常；新版 controls/信息保留，多行 tenet 可滚动，无空白溢出 |
| L2-01 | 创建/改革 | 初始默认教义正确；可选第 4 个及后续 tenet；选择/替换/取消/重开正常，费用和互斥跟原生一致 |
| L2-02 | 空槽与边界 | 使用代表性数量（3、4、多行及100槽边界）；不能用重复教义占满；不用空槽的信仰创建后所有 placeholder 均移除，真实教义保留 |
| L2-03 | 原版钩子 | 创建/改革后原版副作用正常，无因 mod 覆盖丢失的原生 on_action；日志不出现无效 scope 或 missing doctrine |
| L2-04 | 存读档 | 对已创建扩槽信仰保存、冷加载；真实教义/费用/面板稳定，空槽不复活。旧版存档只用外置副本，取得时记录来源和边界 |
| L2-05 | 文化传统 | cap 生效，新增传统入口和费用正常；超过原版默认上限的代表性场景通过，不穷举 10000 |
| L2-06 | 语言与 DLC | 中英文界面必要 key 正常；记录当次 DLC，检查 DLC gating 保留，不把单一组合外推为全部组合 |

## 证据和结果

采用框架本机任务总线/排他、`ck3_live_run_id`、MCP-first、Steam 离线和正式日志分析合同；每次 attempt 保存输入快照、实际命令、日志、状态读回、必要截图和最终报告。不改写 RED；纯 Python 修复且加载输入未变时按框架热重试。产品夹具必须外置，不能进入发行目录。

结果分为 `incompatible`、`static-ready`、`live-verified` 和 `environment-blocked`；表中每项逐一登记 PASS/FAIL/NOT-RUN 与原因。只有新版实机关键路径通过，才能称 `live-verified`；当前 `NOT-RUN`。通用成果归属判定和框架提交链接同时入产品报告。
